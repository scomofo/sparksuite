# Manifest Auto-Update Handoff

## What This Is

The manifest system eliminates manual index.html edits for instrument loading.
When instruments are generated or integrated, the manifest is updated automatically,
and the discovery loader reads it at runtime to inject script tags.

## Files

| File | Purpose |
|------|---------|
| js/instruments/instrument_manifest.generated.js | Declares all registered instruments and their script paths |
| js/instruments/discovery_loader.js | Reads manifest and injects script tags at runtime |
| scripts/apply_generated_instrument.js | Updates manifest + index.html after generation |

## How the Manifest Works

instrument_manifest.generated.js exports a global array:

    window.SPARK_INSTRUMENT_MANIFEST = [
      { id: "chordspark", instrument: "guitar", scripts: [...] },
      { id: "pianospark", instrument: "piano", scripts: [...] },
      ...
    ];

Each entry lists the script paths in load order.

## How Discovery Works

discovery_loader.js runs early in the page lifecycle:

1. Reads window.SPARK_INSTRUMENT_MANIFEST
2. For each instrument, creates script tags in order
3. Appends them to document.head
4. Instruments self-register via SparkInstruments.register()

## When the Manifest Updates

The manifest is regenerated by:
- scripts/apply_generated_instrument.js (after generating a new instrument)
- scripts/generate_instrument_pipeline.js (can call apply automatically)
- Manual: node scripts/apply_generated_instrument.js --rebuild-manifest

## Constraints

- Browsers cannot scan directories, so manifest must be pre-built
- Script load order within each instrument matters (data before register)
- The manifest is a generated file and should not be hand-edited
- Discovery loader must be loaded before any instrument files

## Verification

After manifest update:

1. Check instrument_manifest.generated.js lists all expected instruments
2. Verify script paths exist on disk
3. Open app in browser, check console for 404 errors
4. Verify all instruments appear in launcher
